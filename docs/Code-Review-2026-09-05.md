# SlideSCI Focus 代码审查与优化（2026-09-05）

## 范围与结论

基于本地提交 `00bc606`（2.0.1.0），开始时工作区干净。检查了 VSTO 项目与启动、Ribbon 功能入口、放大图参数与形状生成、公式子进程、代码高亮、导出和构建脚本。此次为有针对性的静态审查与故障回归，不代表全部功能或 Office 版本已验收。

项目已有独立 PowerPoint 上下文守卫、放大图帮助类和直接部署脚本，可在现有结构上持续改进。优先级应是操作失败时保留文档和设置，其次是长任务响应性、模块拆分和 Figure 功能扩展。

## 本轮已实施（2.0.2.0）

1. **公式转换超时覆盖整个通信过程。** 原实现同步写完 stdin 才开始读取输出并计时；子进程不消费输入，或先写满 stderr，可能使大输入永久阻塞。现在先并行读取 stdout/stderr，在工作线程写入无 BOM UTF-8 输入，以一个 60 秒截止时间等待输入、输出和进程退出。超时请求终止进程，并观察终止引发的任务异常。子进程提前退出时优先保留其错误诊断。
2. **设置读写校验。** XML 内的 NaN/INF、超范围尺寸、非法枚举、颜色和线型回退为字段默认值。窗口初始化同样防御直接传入的非法设置；规范化使用副本，不修改调用者对象。
3. **设置原子保存与明确反馈。** 先序列化到同目录唯一临时文件，再替换目标。保存失败保留旧文件、清理临时文件并返回失败；Ribbon 提示本次参数有效但没有持久化。保留 Focus 优先、旧目录只读回退的迁移规则。
4. **Windows 构建入口。** 明确解析 npm.cmd，避免命中 npm.ps1 包装脚本。程序集、应用版本及 Inno 默认版本统一为 2.0.2.0。
5. **可重复回归。** `tests/Run-CoreRegression.ps1` 针对实际 Release DLL 编译 .NET Framework 测试程序，使用独立临时目录与可控子进程，不访问用户配置或打开 PowerPoint。包含真实 60 秒超时场景。
